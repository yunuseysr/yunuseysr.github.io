Parquet in the browser with DuckDB-WASM

“What is in this Parquet file?” usually means opening a notebook or a Spark shell. A static web page can answer it in two seconds — schema, row groups, a column profile, ad-hoc SQL, even CSV → Parquet — without the file ever leaving the machine.

Why DuckDB

DuckDB is an in-process analytical database with first-class Parquet, CSV and JSON readers. Its WebAssembly build runs the same engine in a Web Worker. For a static site that is ideal: no backend to run, no upload, and the same SQL you would write on a laptop.

The cost is size: the engine is about 7 MB. The data explorer loads it only when you open that tool, so nothing else on the site gets heavier.

Starting the engine

const duckdb = await import('https://cdn.jsdelivr.net/npm/@duckdb/duckdb-wasm@1.29.0/+esm');
const bundle = await duckdb.selectBundle(duckdb.getJsDelivrBundles());

// A worker can't be loaded cross-origin directly, so wrap it in a same-origin blob
const workerUrl = URL.createObjectURL(
    new Blob([`importScripts("${bundle.mainWorker}");`], {type: 'text/javascript'}));
const db = new duckdb.AsyncDuckDB(new duckdb.VoidLogger(), new Worker(workerUrl));
await db.instantiate(bundle.mainModule, bundle.pthreadWorker);
const conn = await db.connect();

Reading the user's file without copying it

registerFileHandle lets DuckDB read a dropped File directly. For Parquet it only fetches the byte ranges it needs — the footer, then the row groups a query touches — so even large files open quickly.

await db.registerFileHandle(name, file, duckdb.DuckDBDataProtocol.BROWSER_FILEREADER, true);
await conn.query(`CREATE VIEW data AS SELECT * FROM read_parquet('${name}')`);

After that everything is plain SQL:

-- column profile: min, max, approx. distinct, average, quartiles, null %
SUMMARIZE data;

-- Parquet layout: row groups and compression
SELECT count(DISTINCT row_group_id), string_agg(DISTINCT compression, ', ')
FROM parquet_metadata('events.parquet');

-- convert: write a new file inside the WASM file system, then hand it to the browser
COPY (SELECT * FROM data) TO 'out.parquet' (FORMAT PARQUET, COMPRESSION ZSTD);
const bytes = await db.copyFileToBuffer('out.parquet');   // Uint8Array → Blob → download

In the tool, a 108 KB CSV of 2 000 orders becomes a 23 KB Parquet file this way.

Gotchas

  • BigInt. count(*) and BIGINT columns come back as JavaScript BigInt; JSON.stringify throws on them unless you convert first.
  • Timestamps arrive from Arrow as epoch milliseconds — format them by the column type, not by guessing from the value.
  • Testing. In my tests, headless Chrome's “virtual time” mode never finished instantiating the engine; driving the page in real time (over the DevTools protocol) worked.

Tarayıcıda Parquet: DuckDB-WASM

“Bu Parquet dosyasında ne var?” sorusu genelde bir notebook ya da Spark shell açmak demek. Statik bir web sayfası bunu iki saniyede cevaplayabilir: şema, satır grupları, sütun profili, anlık SQL, hatta CSV → Parquet. Üstelik dosya bilgisayardan hiç çıkmadan.

Neden DuckDB

DuckDB, Parquet, CSV ve JSON okuyucuları birinci sınıf olan, uygulamanın içinde çalışan analitik bir veritabanı. WebAssembly sürümü aynı motoru bir Web Worker içinde çalıştırıyor. Statik bir site için ideal: çalıştırılacak sunucu yok, yükleme yok ve dizüstünde yazacağın SQL'in aynısı.

Bedeli boyut: motor yaklaşık 7 MB. Veri gezgini onu yalnızca o aracı açtığında yüklüyor; sitenin geri kalanı ağırlaşmıyor.

Motoru başlatmak

const duckdb = await import('https://cdn.jsdelivr.net/npm/@duckdb/duckdb-wasm@1.29.0/+esm');
const bundle = await duckdb.selectBundle(duckdb.getJsDelivrBundles());

// Worker başka bir alan adından doğrudan yüklenemez; aynı kaynaklı bir blob ile sar
const workerUrl = URL.createObjectURL(
    new Blob([`importScripts("${bundle.mainWorker}");`], {type: 'text/javascript'}));
const db = new duckdb.AsyncDuckDB(new duckdb.VoidLogger(), new Worker(workerUrl));
await db.instantiate(bundle.mainModule, bundle.pthreadWorker);
const conn = await db.connect();

Kullanıcının dosyasını kopyalamadan okumak

registerFileHandle, bırakılan File nesnesini DuckDB'nin doğrudan okumasını sağlıyor. Parquet'te yalnızca ihtiyaç duyduğu bayt aralıklarını alıyor (önce dosyanın sonundaki metadata, sonra sorgunun dokunduğu satır grupları); büyük dosyalar bile hızlı açılıyor.

await db.registerFileHandle(name, file, duckdb.DuckDBDataProtocol.BROWSER_FILEREADER, true);
await conn.query(`CREATE VIEW data AS SELECT * FROM read_parquet('${name}')`);

Gerisi düz SQL:

-- sütun profili: min, max, yaklaşık farklı değer, ortalama, çeyrekler, null %
SUMMARIZE data;

-- Parquet yerleşimi: satır grupları ve sıkıştırma
SELECT count(DISTINCT row_group_id), string_agg(DISTINCT compression, ', ')
FROM parquet_metadata('events.parquet');

-- dönüştürme: WASM dosya sistemine yeni bir dosya yaz, sonra tarayıcıya ver
COPY (SELECT * FROM data) TO 'out.parquet' (FORMAT PARQUET, COMPRESSION ZSTD);
const bytes = await db.copyFileToBuffer('out.parquet');   // Uint8Array → Blob → indir

Araçta 2 000 siparişlik 108 KB'lık bir CSV bu yolla 23 KB'lık bir Parquet dosyasına dönüşüyor.

Dikkat edilecekler

  • BigInt. count(*) ve BIGINT sütunlar JavaScript BigInt olarak geliyor; önce dönüştürmezsen JSON.stringify hata veriyor.
  • Zaman damgaları Arrow'dan epoch milisaniye olarak geliyor; değere bakıp tahmin etmek yerine sütun tipine göre biçimlendir.
  • Test. Benim testlerimde headless Chrome'un “sanal zaman” modunda motor başlatma hiç bitmedi; sayfayı gerçek zamanlı sürmek (DevTools protokolü üzerinden) işe yaradı.
