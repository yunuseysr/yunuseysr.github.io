How Grid Tile picks a grid

You ask for 6 windows; it gives you 3 × 2. You ask for 8; you get 4 × 2. On a portrait monitor the same 6 become 2 × 3. All of it comes from one small scoring function.

The problem

Grid Tile is a GNOME Shell extension that puts the windows on your screen into an even grid. The interesting part is not moving windows — Mutter does that — but deciding how many columns and rows to use for n windows on a screen of a given size.

A fixed table (6 → 3 × 2, 8 → 4 × 2…) breaks as soon as the monitor is portrait, ultrawide, or has a tall top bar. So the extension tries every possibility and keeps the best one.

The rule

For every column count from 1 to n, the rows follow: rows = ceil(n / cols). Then two things are scored:

  1. Cell shape. A browser page or an editor reads best around 4 : 3. The distance from that shape is measured on a log scale, so “twice too wide” and “twice too tall” cost the same.
  2. Empty cells. 7 windows in a 4 × 2 grid leave one cell empty. Each empty cell costs 0.5.

A grid with a completely empty row is never allowed — that is just a smaller grid with wasted space.

export function bestGrid(n, width, height) {
    let best = null;
    for (let cols = 1; cols <= n; cols++) {
        const rows = Math.ceil(n / cols);
        if ((rows - 1) * cols >= n)
            continue;                      // a whole row would be empty
        const aspect = (width / cols) / (height / rows);
        const score = Math.abs(Math.log(aspect / (4 / 3))) + 0.5 * (cols * rows - n);
        if (!best || score < best.score)
            best = {cols, rows, score};
    }
    return best;
}

Look at 9 windows on the portrait screen: a “perfect” 3 × 3 would make each cell very narrow, so the score prefers 2 × 5 and accepts one empty cell. That trade-off is exactly what the 0.5 weight decides.

Two details that matter in practice

Stable cells. The extension takes the most recently used windows, but places them in the order they were opened. Re-tiling therefore never shuffles windows around — your terminal stays in the same corner.

Wayland and maximized windows. Unmaximizing a window restores its old size asynchronously and can override a resize sent right after it. Grid Tile simply applies the geometry once more after 200 ms. Not elegant, but reliable.

Grid Tile ızgarayı nasıl seçiyor

6 pencere istiyorsun, 3 × 2 veriyor. 8 istiyorsun, 4 × 2 geliyor. Dikey monitörde aynı 6 pencere 2 × 3 oluyor. Hepsi tek bir küçük puanlama fonksiyonundan çıkıyor.

Problem

Grid Tile, ekrandaki pencereleri eşit bir ızgaraya dizen bir GNOME Shell eklentisi. İşin ilginç kısmı pencereleri taşımak değil (onu Mutter yapıyor), belirli boyuttaki bir ekranda n pencere için kaç sütun ve kaç satır kullanılacağına karar vermek.

Sabit bir tablo (6 → 3 × 2, 8 → 4 × 2…) monitör dikey, çok geniş ya da üst barı yüksek olduğu anda bozulur. Bu yüzden eklenti bütün olasılıkları deneyip en iyisini seçiyor.

Kural

1'den n'ye kadar her sütun sayısı için satır sayısı kendiliğinden çıkar: rows = ceil(n / cols). Sonra iki şey puanlanır:

  1. Hücre şekli. Bir web sayfası ya da editör yaklaşık 4 : 3 oranında rahat okunur. Bu orandan uzaklık logaritmik ölçekte hesaplanır; “iki kat geniş” ile “iki kat uzun” aynı cezayı alır.
  2. Boş hücreler. 4 × 2 ızgarada 7 pencere bir hücreyi boş bırakır. Her boş hücre 0,5 puan cezadır.

Tamamen boş bir satır bırakan ızgaraya hiç izin verilmez; o aslında boşa yer harcayan daha küçük bir ızgaradır.

export function bestGrid(n, width, height) {
    let best = null;
    for (let cols = 1; cols <= n; cols++) {
        const rows = Math.ceil(n / cols);
        if ((rows - 1) * cols >= n)
            continue;                      // koca bir satır boş kalırdı

        const score = Math.abs(Math.log(aspect / (4 / 3))) + 0.5 * (cols * rows - n);
        if (!best || score < best.score)
            best = {cols, rows, score};
    }
    return best;
}

Pratikte önemli iki ayrıntı

Sabit hücreler. Eklenti en son kullanılan pencereleri alıyor ama onları açılış sırasına göre yerleştiriyor. Böylece tekrar dizdiğinde pencereler yer değiştirmiyor; terminalin hep aynı köşede kalıyor.

Wayland ve büyütülmüş pencereler. Bir pencereyi küçültmek eski boyutunu eşzamansız geri yüklüyor ve hemen ardından gönderilen yeniden boyutlandırmayı ezebiliyor. Grid Tile geometriyi 200 ms sonra bir kez daha uyguluyor. Zarif değil ama güvenilir.
